# 타브만든댕

원곡의 BPM·박 위치를 분석하고, AI로 기타를 분리해 여러 음을 추정한 타브를 만드는 Windows 데스크톱 앱입니다. 노래 재생 시 박·마디선과 현재 음을 함께 표시합니다.

## 실행

1. **`TabMaker_Dd.exe`를 더블클릭**합니다. `실행.bat`으로도 같은 앱을 실행할 수 있습니다.
2. **노래 파일 열기**로 음원을 선택합니다. 창으로 파일을 끌어놓거나 **샘플 멜로디 불러오기**를 눌러도 됩니다.
3. 완성곡은 **완성곡 · AI로 기타 먼저 분리**, 미리 분리한 트랙은 **기타만 있는 음원 · 직접 채보**를 선택합니다. 리듬 기타는 여러 음을, 리드 기타는 주 멜로디를 추정합니다.
4. 튜닝, 최대 프렛, 분석 시작 시간과 길이를 선택하고 **타브 만들기**를 누릅니다. 처음에는 짧은 구간으로 결과를 확인하는 편이 좋습니다.
5. 자동 BPM을 확인합니다. 반/두 배로 잡혔다면 **÷2 / ×2**, 박자표가 다르면 **4/4 · 3/4 · 6/8**, 시작이 어긋나면 **첫 마디 (초)**를 고르고 **박자 적용**을 누릅니다.
6. **재생**하면 현재 마디에 배경색이 표시되고, 주황색 재생선과 현재 프렛/코드 강조가 움직입니다. 화면에는 2/4/8마디를 표시할 수 있습니다.
7. TXT/JSON을 저장하거나 **분석한 기타 음원**을 저장해 기타 분리 결과를 들어볼 수 있습니다. 이 WAV는 분석 시작부터의 구간이므로 원곡과 비교할 때 시작 시간을 더해야 합니다.

화면·재생에는 Windows 10/11 x64, .NET Framework 4.8, 오디오 출력 장치가 필요합니다. 브라우저, 서버, API 키는 필요 없습니다. **BPM/AI 채보 기능은 로컬 Python 분석 환경과 모델에 의존합니다.** 이 PC는 `ai-engine.json`으로 `.ai-upgrade`의 RoFormer/Basic Pitch 엔진을 사용합니다. 설정이 없으면 같은 상위 폴더의 `음원분리댕/.venv`와 `음원분리댕/models`를 찾습니다. EXE만 다른 PC로 복사하면 AI 분석까지 자동 설치되지는 않습니다.

다른 설치 위치는 EXE 옆 `ai-engine.json`에 Python 실행 파일의 절대 경로인 `python`과 모델 루트의 절대 경로인 `models`를 지정하세요. `ai-engine.example.json`이 예제입니다. 분석 코드는 EXE에 포함되며 실행 시 로컬 앱 데이터에 풉니다. 가중치를 자동 다운로드하지 않으며, 모델·환경이 없으면 명확한 오류를 표시합니다.

## 현재 기능

### 새 엔진 설치 및 검증 상태

`고급엔진설치.bat`은 기존 환경과 별개인 `.ai-upgrade`에 기타 전용
[becruily Mel-Band RoFormer](https://huggingface.co/becruily/mel-band-roformer-guitar)와
[Spotify Basic Pitch](https://github.com/spotify/basic-pitch)를 설치합니다.
기존 수작업 하모닉 피팅 대신 학습된 채보 모델을 사용하는 교체 후보입니다.
이 곡에서 더 정확하다는 비교 결과는 아직 없으며, 리드 기타 전용 분리 모델도 아닙니다.

Python 3.10, 인터넷 연결, 패키지·모델을 받을 디스크 공간이 필요합니다.
기본은 CUDA 11.8용 PyTorch이며, GPU 메모리 부족/드라이버 문제 시
`고급엔진설치.bat --cpu`로 CPU 환경을 설치할 수 있습니다 (처리 속도는 느릴 수 있습니다).
설치기는 모델 파일의 SHA256을 확인하고 실제 분리·채보 실행 및 노트 출력을 시험한 뒤에만
`ai-engine.json`을 새 환경으로 전환합니다. 기존 설정은 백업하며, 실패하면 전환하지 않습니다.
합성 신호로 한 실행 시험은 실제 노래의 정답 타브 정확도 검증과 다릅니다.

2026-11-13 사용자 다운로드 완료 후 로컬 체크섬 및 의존성을 확인하고 새 엔진으로 전환했습니다.
audio-separator 0.48.0이 마스크 계층 생성 시 모델의 `mlp_expansion_factor=1`을 누락하는
호환성 문제는 앱 어댑터에서 보정했습니다. 모델 가중치/원본 설정 파일은 변경하지 않았습니다.
합성 음원의 실제 RoFormer 분리·Basic Pitch 추론, EXE의 새 엔진 호출 및 재생/UI 통합 시험을
통과했습니다. **실제 노래 분리 품질과 정답 타브 정확도는 아직 미검증입니다.**
다운로드 후 검사만 다시 수행하려면 `고급엔진설치.bat --verify-only`를 실행하세요.
이 검사는 재다운로드 없이 실제 추론까지 수행하고 성공한 경우 새 엔진 설정을 적용합니다.
분석 중 자동 다운로드는 하지 않습니다. 새 결과 JSON에는 원곡 경로, 분리·채보 모델과
리드/코드 선택을 함께 기록합니다. 원곡 경로가 포함된 결과를 공유할 때 참고하세요.

### 기본 엔진 기능

- 최대 200MB / 30분의 로컬 음원, 드래그 앤 드롭
- Windows Media Foundation으로 MP3, WAV, M4A 등의 음원 디코딩. 실제 지원 형식은 PC의 코덱에 따라 다릅니다.
- 별도 데스크톱 창, 원곡 재생, 전체 곡 또는 30/60/90초 구간 분석, 분석 취소
- 원곡의 스펙트럼 변화·자기상관으로 BPM 추정, DP 박 추적으로 국소적인 박 위치 변화 반영
- Demucs `htdemucs_6s` 기타 분리 후 희소 하모닉 피팅으로 다중 음을 추정. 악보 정답을 보장하는 모델은 아닙니다.
- 반복 피킹 분리, 짧은 오검출 억제, 반대 위상 스테레오의 소실 방지
- 실제 노트 시작 시간과 길이에 비례하는 타브 배치
- 하드웨어 오디오 재생 시간을 기준으로 재생선 이동, 현재 프렛 강조, 자동 스크롤
- 타브 클릭/슬라이더로 원곡 위치 이동, 일시정지, 분석 시작으로 이동, 구간 반복
- 0.5 / 0.75 / 1 / 1.25배 재생. 현재 속도 변경은 음 높이도 함께 바꿉니다.
- 박·마디선, 현재 마디 강조, 2/4/8마디 범위, 마우스 휠 탐색과 자동 따라가기
- Standard / Drop D / 반음 다운 튜닝, 12·17·24 프렛 제한
- 동시에 울리는 음의 줄 중복과 프렛 간격을 고려한 운지 선택
- 마디별 TXT 타브와 BPM·박 위치·음 시점을 포함한 JSON 내보내기
- 스페이스바로 재생/일시정지 (시간 입력칸 등 편집 중에는 제외)

음원은 외부로 업로드하지 않습니다. 원곡 재생용 PCM 임시 파일은 다른 곡을 열거나 정상 종료하면 삭제합니다. AI 결과 JSON과 기타 WAV는 `%LOCALAPPDATA%\TabMaker_Dd\analyses`에 분석별로 보관하며 자동 삭제하지 않습니다. 앱을 종료하면 화면의 작업은 초기화되므로 필요한 결과를 내보내주세요.

## 정확도와 범위

이전 버전이 완성곡에서 한 음만 고르던 문제를 기타 분리와 다중 음 추정으로 변경했습니다. **실제 곡의 정답 타브와 일치한다고 검증한 상태는 아닙니다.** 분리 후에도 보컬·베이스의 누출, 기타 여러 파트의 혼합, 왜곡음과 약한 음 때문에 잘못된 음/옥타브 또는 누락이 남을 수 있습니다. 원곡만으로 실제 연주자가 사용한 줄과 프렛을 유일하게 알 수도 없습니다. 벤딩, 슬라이드, 해머링, 풀링 같은 주법은 구분하지 않습니다.

자동 추정하는 것은 BPM과 박 시점이며, **박자표와 첫 강박/첫 마디를 확정하지 않습니다.** 기본은 4/4로 묶은 마디이고 첫 검출 박을 기준으로 합니다. 못갖춘마디, 6/8, 템포가 변하는 곡, 느리거나 불규칙한 곡은 직접 확인해야 합니다. 규칙적인 박을 못 찾으면 임의의 BPM을 만들지 않고 수동 입력을 요청합니다. BPM 보정은 음의 시점을 강제로 양자화하지 않습니다.

타브의 가로 간격과 노트 꼬리는 추적한 박 위치를 기준으로 합니다. TXT는 마디별로 나누고 같은 시점의 코드 음을 같은 열에 놓지만, 칸 폭이 음 길이에 비례하지는 않습니다. JSON의 `start`와 `duration`은 원곡 기준 초입니다. `?`는 음역 밖 또는 다른 음과 충돌해 운지를 배치하지 못한 가설입니다. `relativeStrength`는 분석 내 상대 강도이며 정확도 확률이 아닙니다.

## 데스크톱 소스와 빌드

- `desktop/MainWindow.xaml`, `Program.cs`: WPF 데스크톱 화면과 재생/분석 제어
- `desktop/Audio.cs`: Media Foundation 디코딩, 분석용 다운샘플링, 원곡 PCM 캐시
- `desktop/WavePlayer.cs`: Windows waveOut 오디오 큐와 실제 재생 시계, 탐색/반복/속도 변경
- `desktop/Analysis.cs`, `TabView.cs`, `Rhythm.cs`: 운지 탐색, 동시 음과 박·마디 렌더링, 박/시간 변환
- `desktop/AiEngine.cs`, `engine/transcribe.py`: 설치 환경 탐색, Python 제어, AI 분리·채보·BPM 추정
- `desktop/SelfTest.cs`: 디코딩·분석·실제 오디오 재생·UI 연동 검증
- `desktop/build.ps1`, `app.manifest`: .NET Framework 컴파일러로 단일 EXE 빌드

프로젝트 폴더의 PowerShell에서 `powershell -ExecutionPolicy Bypass -File .\desktop\build.ps1`로 빌드합니다. Windows의 .NET Framework C# 컴파일러를 사용하며 NuGet 의존성은 없습니다.

구현 참고: [Windows 디코딩 API](https://learn.microsoft.com/en-us/windows/win32/api/mfreadwrite/nn-mfreadwrite-imfsourcereader), [Demucs 기타 분리 모델](https://github.com/facebookresearch/demucs), [DP 박 추적 방법](https://librosa.org/doc/main/api/generated/librosa.beat.beat_track.html). 외부 코드를 그대로 붙인 것으로 표시하는 자료가 아니라 구현 시 참고한 API/알고리즘 자료입니다.

기존 `index.html`, `style.css`, `app.js`, `pitch-worker.js`, `server.py`는 이전 웹 버전의 소스입니다. 기본 실행은 EXE이며 웹 버전은 `python server.py`로 별도 실행할 수 있습니다. 웹 버전에는 새 데스크톱 재생 연동 기능이 들어 있지 않습니다.

## 검증

`TabMaker_Dd.exe --self-test desktop-test.txt`는 직접 기타 음원 분석과 재생/UI 통합 시험입니다. `--with-ai`를 마지막에 추가하면 실제 Demucs 추론도 실행합니다. 음원은 무음으로 출력하며 시험 창은 투명하게 실행합니다. 결과는 TXT와 PNG로 저장됩니다.

`engine/test_engine.py`는 합성 80/100/120/150/180 BPM과 박 위상, 단음·3음 코드, 왜곡 코드, 작은 소리·무음, 반복 피킹, 반대 위상 스테레오를 검증합니다. Python에는 설치된 AI 환경의 실행 파일을 사용하세요. 모델 루트를 인자로 추가하면 합성 혼합 신호로 실제 Demucs 추론을 별도로 검증합니다.

EXE에서는 Python 연동, BPM 추정, 박/시간 변환, 마디 경계·수동 보정, 동시 음의 줄 배치와 강조, TXT/JSON, 원곡 기준 구간 시간, 실제 오디오 시계의 진행/정지/배속/탐색/반복을 검증했습니다. **이는 실제 노래의 정답 타브 정확도 시험을 대체하지 않습니다.** 구체적인 변경·실패·검증 결과는 `프로젝트기록.md`에 계속 누적합니다.
